# 系统预览处理器托管设计（v1）

> 背景：直接复用资源管理器预览窗格的那套能力（Preview Handler / `IPreviewHandler`），
> 让文档预览呈现真实排版；不可用时回落既有的零依赖解析链（见 docs\文档预览功能设计.md）。
> 方案选择：**混合式（Handler 优先、既有链路兜底）+ 从一开始就独立宿主进程隔离**。

## 1. 为什么可行

Explorer 预览窗格（Alt+P）只是一个宿主。预览处理器是公开的 COM 接口
（[IPreviewHandler](https://learn.microsoft.com/windows/win32/api/shobjidl_core/nn-shobjidl_core-ipreviewhandler)、
[预览处理器与 shell 预览宿主](https://learn.microsoft.com/windows/win32/shell/preview-handlers)），
任何程序都可以自己当宿主：`CoCreateInstance(CLSID)` → 装入文件 → `SetWindow(hwnd, rect)` → `DoPreview()`。

本机注册表实测（`HKLM\...\PreviewHandlers` + 扩展名关联）可用处理器覆盖：
Microsoft PDF（Edge）、Foxit PDF、Word/Excel/PPT/Visio、WPS 文字/表格/演示、TXT/RTF、字体、压缩包等 20+。

## 2. 架构（与 Explorer 的 prevhost.exe 同构）

```
轻启主进程 (WPF)                          QuickPalette.PreviewHost.exe (x64, STA)
┌─────────────────────────┐              ┌──────────────────────────────────────┐
│ PreviewWindow           │  启动/终止    │ 解析扩展名 → CLSID                    │
│  └─ PreviewSlotHost     │─────────────▶│ CoCreateInstance → 装入文件           │
│     (槽位 HWND)         │  stdout 行协议│ SetWindow(槽位HWND, rect)             │
│     ▲ 挂载点            │◀─────────────│ DoPreview() → READY                   │
│     │                   │  READY/CLOSE │ 消息泵 + 父窗口看门狗                  │
└─────────────────────────┘  /FAIL …     └──────────────────────────────────────┘
        处理器内容窗口跨进程挂进槽位（LocalServer32 的 Word/WPS 由 COM 再起独立进程）
```

- **崩溃隔离**：处理器是第三方 COM 代码，崩溃/卡死只带走宿主进程；主进程观察到异常退出
  即回落自有链路（这正是选择"一开始就独立进程"的原因）。
- **生命周期**：单击文档结果 → 启动宿主；切换/隐藏/退出 → 终止宿主；
  宿主侧另有看门狗（槽位 HWND 消失即退出），主进程异常退出不留孤儿。
- **通信**：stdout 行协议 `READY` / `CLOSE` / `FAIL <NOHANDLER|INIT|ARGS> <消息>`；
  退出码 0=正常/关闭（处理器内 Esc 等），2=无处理器，3=初始化失败，4=参数无效。

## 3. 关键实现细节

### 3.1 扩展名 → CLSID 解析（`PreviewHandlerResolver`，与 Explorer 同语义）

1. `HKCR\{ext}\ShellEx\{8895b1c6-b41f-4c1c-a562-0d564250836f}`
2. `HKCR\{ProgId}\ShellEx\{8895b1c6-...}`（ProgId = `HKCR\{ext}` 默认值）
3. `HKCR\SystemFileAssociations\{PerceivedType}\ShellEx\{8895b1c6-...}`
   （txt/md 等按感知类型关联；**PerceivedType 是 .ext 键上的命名值，不是子键**）

注册信息按 64 位视图 → WOW6432Node 顺序读取；解析结果按扩展名缓存。

### 3.2 位数（双位数宿主，x64 + x86）

- `LocalServer32`（Word/Excel/PPT/WPS 预览器多为此类）：任意位数宿主可激活，
  由 COM 跨进程封送——**32 位注册表视图里注册的 CLSID 实测也能被 x64 宿主激活**。
- `InprocServer32`：探测 DLL 的 PE 头（`ProbePeArch`），按位数定向宿主——
  64 位 DLL 用 `QuickPalette.PreviewHost.exe`，32 位 DLL（WPS 系插件、Foxit 等）
  用 `QuickPalette.PreviewHost32.exe`（x86）；探测不出的两种宿主依次尝试。
- **x86 宿主必须放独立子目录**（`previewhost32\`）：自包含运行时文件名与 x64 相同
  （hostfxr/coreclr/...），平铺同一目录会错配导致 `0x800700C1`（实测踩过）。

### 3.3 装入入口三级回退（处理器实现哪种就用哪种）

`IInitializeWithFile` → `IInitializeWithStream`（`SHCreateStreamOnFileEx` 开流；
Windows TXT/RTF 预览器**只**支持这种，经实测确认）→ `IPersistFile`。
失败时输出各入口 HRESULT 便于定位。

### 3.4 交互融合

- 站点：`IObjectWithSite::SetSite(宿主框架)`，实现 `IPreviewHandlerFrame`
  接收处理器回传的按键；Esc = 关闭请求（`CLOSE` → 隐藏预览）。
- 主题：`IPreviewHandlerVisuals::SetBackgroundColor` 传入当前主题背景色（RRGGBB）。
- 焦点：处理器内容窗口是预览窗口的跨进程子窗口，激活仍落在预览窗口上，
  既有"焦点不离开应用就不收面板"的逻辑无需改动。
- DPI：宿主清单声明 PerMonitorV2，挂载矩形取槽位客户区物理像素。

## 4. 混合式回落链（任何机器都有得看）

| 优先级 | 模式 | 适用 |
|---|---|---|
| 1 | Handler 模式（本设计） | 有关联处理器且可承载（真实排版、可滚动/选中） |
| 2 | 图像模式 | 图片文件直出位图；PDF 走 Windows.Data.Pdf 渲染桥 |
| 3 | 文本模式 | DocumentTextExtractor 零依赖抽取（txt/md/docx/pptx/xlsx） |
| 兜底 | 明确的"不支持/失败"提示 | 如实标注，不假装 |

回落触发条件：无关联 / 处理器位数不匹配 / 宿主缺失 / 就绪超时（12s，Word/WPS 冷启动）/
初始化失败 / 就绪后崩溃。文本模式本来就覆盖 txt/md，故 shell32 特殊处理器即便
装入失败也无体验损失。

## 6. 已验证

- 单元测试：解析三级链、LocalServer/InProc 承载判定、PE 架构探测（238 项通过）。
- 端到端冒烟：TXT 处理器（shell32，仅支持流装入）经槽位 HWND 挂载输出 `READY`；
  无处理器扩展名 `FAIL NOHANDLER`、坏参数 `FAIL ARGS` 均按协议退出。
- Debug/Release 全量构建通过。

## 3.5 WPF 集成的两个实测坑（都以截图/窗口树实测定位）

1. **`AllowsTransparency="True"` 分层窗口不合成子 HWND 的内容**：
   处理器加载成功、文本在控件里（WM_GETTEXT 可取），但屏幕上纯空白。
   预览窗口因此改用普通窗口 + `WindowChrome`（DWM 圆角/阴影），视觉基本不变。
2. **Collapsed→Hidden 后立即量槽位尺寸会拿到 HwndHost 初建的 1×1**：
   该尺寸传给 `SetWindow` 后处理器只画 0×1 的区域。
   解决：按最小合理尺寸（40px）判定 + 布局重试（间隔让 Dispatcher 落地排列）。
3. 教训：集成层必须**验屏幕像素**（实拍截图），仅验 `READY`/控件文本会被上述两类问题骗过。

## 7. 打包注意（本工作区实测）

本工作区根目录被环境打了「低」完整性标签，其下**新建**目录（如 `dist\`）会继承该标签；
从低完整性标签的 exe 启动的进程受强制完整性控制约束，COM 交互会被拒
（`DoPreview` 阶段 `E_ACCESSDENIED`，同一二进制换到中完整性目录即正常）。
打包产物请输出/复制到中性目录再分发（本次交付在 `D:\Desktop\轻启安装包\`）；
安装到虚拟机后文件随目标目录生成，不受此影响。
