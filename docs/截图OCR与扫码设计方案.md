# 截图 OCR 与扫码 · 调研与设计方案

> 需求：截图框选后，支持对选区内容 **OCR 提取文字**；选区含 **二维码** 时可扫码直达/复制内容。
> 本文为调研结论与设计，**经确认后动工**。

---

## 一、结论速览（TL;DR）

| 项 | 选型 | 理由 |
|---|---|---|
| OCR 引擎 | **Windows.Media.Ocr（系统 OCR）** | 零体积、离线、中英混排够用、与截图/录屏同走系统 API 的产品哲学一致 |
| 二维码识别 | **ZXing.Net**（NuGet） | 事实标准、纯托管、~500KB、解码快且容错好 |
| 交互 | 工具条新增 [OCR] [扫码] 两按钮 | 复用现有截图流程与提示卡风格 |
| 新增体积 | **≈ 0.5MB**（仅 ZXing.Net） | 对比 PaddleOCR 方案省 ~15MB 模型 |
| SVG 图标 | 需 2~3 枚（见 §6 清单） | 沿用 ToolbarIcons 48×48 iconfont 体系 |

---

## 二、OCR 方案对比

| 方案 | 中文质量 | 体积增量 | 速度 | 离线 | 维护/生态 | 结论 |
|---|---|---|---|---|---|---|
| **Windows.Media.Ocr（系统）** | 良（印刷体强，手写一般） | **0** | 快（<0.5s） | ✓ | 系统组件，永续 | ✅ **首选** |
| PaddleOCR (PP-OCRv4/v5, ONNX) | 优（业界标杆，中英混排最强） | ~15MB 模型 + OnnxRuntime | 1~2s（CPU） | ✓ | GitHub 45k+ star | 🔜 增强版备选 |
| RapidOCR（ONNX 精简版） | 优（Paddle 同源蒸馏） | ~10MB | ~1s | ✓ | 2k+ star，上升期 | 备选 |
| Tesseract | 中（中文排版差） | ~40MB traineddata | 1~2s | ✓ | 62k star 但老旧 | ❌ 不选 |

**为什么 Windows OCR 是对的**：
1. **与产品调性吻合**：轻启的截图（GDI/WGC）、录屏（WGC）、预览窗（系统预览处理器）全走系统能力——OCR 继续用系统引擎是同一设计哲学；微软自家截图工具（Win+Shift+S 的"文本操作"）就是 Windows OCR。
2. **零依赖零体积**：识别引擎随系统语言包存在（中文系统默认有"中文(简体)"OCR 包；Win10 1809+ 即可用）。
3. **实际质量**：ShareX（35k star）的 OCR 默认即 Windows OCR；Cherry Studio 等桌面工具同款方案。印刷体/截图文字识别率与 Paddle 差距在 5~10% 量级，而截图场景 95%+ 是印刷体。
4. **留升级口**：`IOcrEngine` 接口抽象，PaddleOCR(RapidOCR) 作为 v2 可插拔增强（设置里可选"高精度引擎"），不阻塞本期。

**边界**：系统未装 OCR 语言包时（精简系统常见）→ 引导提示"设置→语言→添加中文(可选功能)"，不崩溃。

## 三、二维码方案对比

| 方案 | 语言 | 解码能力 | 体积 | 结论 |
|---|---|---|---|---|
| **ZXing.Net** | C# 原生 | QR/条码全家桶，容错（模糊/倾斜/反色）良好 | ~500KB | ✅ 选 |
| ZBar（P/Invoke） | C | 快 | 原生 dll 分发 | 绑定麻烦 |
| QRCoder | C# | **只生成** | — | 不适用 |
| OpenCV QRCodeDetector | C++/绑定 | 强 | +30MB | 过重 |

ZXing.Net 是桌面二维码识别的**事实标准**（ShareX、Greenshot 系工具同款），NuGet 活跃维护，支持 `Bitmap` 直喂、多码同图识别（`decodeMultiple`）——满足"一张截图多个二维码列出选择"。

## 五、交互设计

### 5.1 入口：截图工具条新增两枚按钮

```
[框选][矩形][椭圆][箭头][画笔][高亮][文字][马赛克][橡皮] | [撤销][重做] | [长截图][录屏] [OCR][扫码] | [复制][保存][贴图][关闭]
```

- **[OCR]**（图标：扫描框+文字）：识别选区文字 → 打开结果面板
- **[扫码]**（图标：二维码）：识别选区二维码 → 弹跳转卡片（识别中按钮转圈；未识别到 → 轻提示"未发现二维码"）

### 5.2 OCR 结果面板（新窗口，链接助手同风格深色圆角卡放大版）

```
┌─────────────────────────────────────┐
│ ⌘ 文字识别结果                        │
│ ┌─────────────────────────────────┐ │
│ │ 识别出的文本（可滚动、可选中）      │ │
│ └─────────────────────────────────┘ │
│ 识别语言：中文+英文    耗时 0.4s      │
│ [复制全部]  [复制并关闭]  [搜索此文本] │
└─────────────────────────────────────┘
```

- 文本框支持**手动修正**（OCR 免不了小错）
- 「搜索此文本」= 浏览器搜索（复用网络搜索逻辑）
- 识别中状态：面板内进度点动画；失败 → "未识别到文字"
- **快捷键**：选区后按 `O` 触发 OCR（与长截图 `L` 同风格）；扫码暂不设键

### 5.3 扫码卡片（复用 LinkPromptWindow 视觉）

- 识别到 1 个码：卡片显示图标+内容（URL 显示域名）+「打开」「复制」
- 多个码：卡片内列出全部（点选展开）
- 非 URL 内容（文本/名片）：只显示+「复制」
- 链接类内容**天然接上链接助手智能直跳**（todesk:// 等协议直接拉起）——与现有能力乘法

### 5.4 流程时序

```
框选 → 工具条 [OCR] →(异步识别)→ 结果面板
      → [扫码] →(异步识别)→ 跳转卡片 / "未发现二维码"
      → 键盘 O → 同 [OCR]
```

识别在后台线程（WinRT OCR 本身异步），UI 不卡；识别期间截图层保持可关。

## 七、技术集成点

1. **Bitmap → SoftwareBitmap**（喂给 Windows OCR）：截图现有 `BitmapSource` → `CopyPixels` → `Windows.Storage.Streams.Buffer` → `SoftwareBitmap.CreateCopyFromBuffer`；必要时 `SoftwareBitmap.Convert(Bgra8, Premultiplied)`。
2. **OCR 调用**：`OcrEngine.TryCreateFromUserProfileLanguages()`，优先 zh-Hans+en 双语；`RecognizeAsync` → `Lines`/`Text`。**小字预处理**（Text-Grab 经验）：选区宽 <400px 时按 2x 放大再识别，提升小字号准确率。
3. **二维码**：`ZXing.Net` 的 `BarcodeReader`（`TryHarder = true`、`PossibleFormats = QR_CODE`）+ 反色重试（深底码）一次。
4. **工程结构**：`QuickPalette.App\Ocr\OcrService.cs`、`QrService.cs`、`OcrResultWindow`（XAML，主题 DynamicResources）、`QrPromptWindow`（链接卡片风格）；截图工具条两按钮+`O` 键；设置暂不新增项（二期可加"识别语言/高精度引擎"）。
5. **依赖**：NuGet `ZXing.Net`（net9.0 兼容 ✓）；Windows OCR 走 `net9.0-windows10.0.22621.0` TFM ✓（工程已是）。

## 八、风险与边界

| 风险 | 应对 |
|---|---|
| 精简系统缺 OCR 语言包 | 检测 `OcrEngine.AvailableRecognizerLanguages` 为空 → 引导安装可选功能 |
| 识别质量不及 Paddle（复杂排版/艺术字） | UI 支持手动修正；二期插拔高精度引擎 |
| 二维码模糊/反色/倾斜 | ZXing TryHarder + 反色重试；失败提示明确 |
| OCR 结果隐私 | 全程本地识别，无网络（"本地优先"卖点写进面板小字） |
